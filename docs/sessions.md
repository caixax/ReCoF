## 2026-10-25 (client.dll verification pass of the TODO near-matches)

Method: a scratch checker (symeq.py in the session scratchpad, not committed) disassembles the function from the retail delinked object (build/target) and from ours (build/base) with capstone and executes both symbolically in lockstep, one superblock (up to a conditional branch, switch or ret, following direct jumps) at a time. At every pair of superblocks the entry values are abstracted into classes that hold on every incoming edge (fixpoint over the CFG pair, values of one side may be derived from classes of the other), so register and stack slot choice does not matter. It compares the call sequence (target, stack arguments, this, xmm0/st0 inputs), the stores to memory (multiset per call segment plus the order of possibly aliasing stores), branch conditions (with inversion), switch dispatch (jump and byte index tables decoded per index), the return value and the callee saved registers. Globals are compared by retail address (our symbols through the symbol map or the aligned objdiff rows), constants and string literals by content, memory loads carry an epoch that changes at every call and store. Address taken stack objects are memory with sizes taken from the source declarations when the default (up to the next object, 0x40) is too wide; a frame object is assumed not to alias memory reached through a loaded pointer. Calling conventions come from the decorated names and the retail ret N; function pointer members declared APIENTRY (GLManager, the CgWater extension pointers) were declared stdcall per run. Mutation tests (changed immediates, conditions, argument order, a removed store, switch table entries) were all reported as differences. What the checker can not follow (different branch structure, values set on some paths and read later on the same paths) was read by hand or left TODO.
