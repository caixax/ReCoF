# Translation units and link order (1.6a)

Generated by `tools/make_units.py` from `docs/progress.csv` (and, for hl.dll, the 1.55 PDB). Full lists: `docs/units_hl.csv`, `docs/units_client.csv`.

Columns: `order_1.6a` (position in the 1.6a image), `source_file`, `first_va`/`last_va` (core run of functions attributed to the file), `named_functions`, `functions_in_range` (all functions between first and last, named or not), `order_1.55` and `object_1.55` (hl.dll only, from the PDB section contributions), `origin` (which reference tree has a file of that name), `runs` (1 = all named functions of the file are contiguous).

Only functions defined in a `.cpp`/`.c` file count. Inline functions from headers are placed by the linker in whichever object used them first, so they are attributed to their header and ignored here.

## hl.dll

- 1.6a has 162 compiled objects (Rich header: 159 C++ + 3 C). 152 source files are placed; `dlls/game.cpp`, `dlls/globals.cpp` (data only) and `dlls/h_ai.cpp` are known from 1.55 but none of their functions has been identified in 1.6a yet. The two or three 1.6a-only objects are the MP5 and bowling ball code (classes `CMp5`, `CMP5Ammo`, `CBowlingBall`, `CMP5ModeSaveRestoreMP5`).
- **1.6a link order**: `game_shared/voice_gamemgr.cpp`, then `pm_shared/pm_debug.c`, `pm_math.c`, `pm_shared.c`, then every `dlls/*.cpp` in case-insensitive alphabetical order (`AI_BaseNPC_Schedule`, `alias`, `animating`, `animation`, `bmodels`, `buttons`, `cbase`, `client`, `CoF_3DKeypad`, `CoF_Action`, ...). This is a VS 2019 project whose files sit in "game_shared", "pm_shared" and "dlls" filters.
- **1.55 link order** (VS .NET 2003): one flat alphabetical list over all folders (`pm_*` and `voice_gamemgr` at their alphabetical positions, 136-138 and 152).
- 96 files are CoF-only (`CoF_*.cpp`, `item_*.cpp` and others), 52 come from the HLSDK, 3 from Spirit (`alias.cpp`, `locus.cpp`, `movewith.cpp`), 1 from Paranoia.
- Original source root: `s:\CryofFear\Sourcecode\` in 2012 and `D:\CoFFinalPatch\code\` in 2020 (from the PDB paths), with folders `dlls`, `game_shared`, `pm_shared`, `engine`, `common`.

## Library code

Everything after the last game object is static library code (class LIB in `docs/progress.csv`): hl.dll from 0x10121FE5, client.dll from 0x100B42A4. It matches the exact libraries of the 1.6a build byte for byte (`build/match/*_crt.csv`): MSVC 14.27.29110 `libcmt`, `libvcruntime`, `libcpmt` (internal compiler build 28920) and the Windows SDK 10.0.19041 `libucrt` (build 27412), the same builds the retail Rich header lists. A full link of rebuilt objects against these libraries can therefore reproduce the library part exactly.
