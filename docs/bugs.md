# Bug inventory

Every known problem of the retail game that ReCoF may fix, one row per issue. The sources are the user's reports, the 180 bugs DeCoF found during the decompilation ([original_bugs.md](original_bugs.md)), remarks in DeCoF's progress and session logs, the runtime patches of RebuiltSimon and of the community co-op mod, and public reports. Each row was checked against the source unless its evidence says otherwise.

## Columns

- **ID** is permanent. A new issue takes the next free number in whatever section it belongs to, and numbers are never reused. Fix commits name it: `<binary>: <what was fixed> (<id>)`.
- **Repro** says how to see the problem in game. "None" means there is no visible effect in the shipped game.
- **Severity**, from worst to least:
  - **crash**: the game crashes, hangs or corrupts memory.
  - **save**: saves lose or corrupt state, or persistent progress is wrong.
  - **gameplay**: game logic is wrong, softlocks included.
  - **performance**: frame rate, loading time or memory growth.
  - **visual**: the picture is wrong.
  - **audio**: a sound is wrong, missing or doubled.
  - **cosmetic**: text and menu details.
  - **latent**: wrong code with no visible effect in the shipped game.
- **Runners** is yes when speedrunners rely on the behavior, check when a fix could change something they use and that has to be checked first, and no otherwise. A fix to a yes or check row keeps the original behavior available behind an `rc_` cvar.
- **Status** is open, test (fixed in the source and waiting for an in-game test), fixed (confirmed in game) or keep (decided not to fix, with the reason in the fix plan). `git log --grep <id>` finds the fix commits.

Rows imported from DeCoF can hold several related problems of one function or file. A fix commit names the part it fixes, and the row is fixed when all its parts are.

## Adding an issue

Add a row to the section of its binary, or to "User reports" when it comes from a player and the cause is not known yet, with the next free ID. Check the problem against the source before it goes in, and say in the evidence when it could not be checked. When a user report turns out to have a cause listed elsewhere, link that row's ID in the evidence instead of moving the report.

## Crash dumps

Retail's crashhandler.dll writes a minidump for every crash to Steam's `dumps` folder, for example `C:\Program Files (x86)\Steam\dumps\crash_cof.exe_<time>_1.dmp`. Open it with `cdb -z <file> -c ".ecxr; kb 20; lm o; q"` (the Windows debugger) and name the frames with `python tools/name_addr.py <dll> <offset> ...`, which reads the baseline link maps. The `lm o` list shows what else was loaded: runtime tools such as RebuiltSimon or the co-op mod crash in their own modules, and those crashes do not belong here.
